# lotteon_buy — 롯데온 판 (Node.js / TypeScript)

`bnkr_buy` · `naver_buy` 와 같은 프로그램을 롯데온에 맞춘 것이다. **파이썬 짝은 없다** —
이 판이 원본이다.

```
지켜보기(초 단위) → 구매 가능 감지 → 바로 구매하기 → 주문서 → 필수 동의
                  → 결제하기 → PG 결제창 → [사람] 결제
```

**결제창까지가 끝이다.** 결제창 안에서는 아무것도 누르지 않는다 — 카드 인증도, 간편결제
비밀번호도, 앱 승인도 거기서 사람이 한다. 로그인도 자동화하지 않는다. 브라우저에서
직접 로그인한 세션 쿠키를 빌려 쓴다.

| | 어디서 멈추나 |
|---|---|
| `bnkr` | 결제창을 띄우고, 그 안에서 카카오페이까지 눌러 **QR 을 폰으로 보낸다** |
| `naver` | **주문서**. 네이버는 결제가 끝나야 재고를 깎아서 더 가도 얻는 게 없다 |
| `lotte` | **결제창**. 띄우는 데까지만 간다 |

## 네이버와 달리 — HTTP 조회가 된다

롯데온은 Node 의 요청을 밀어내지 않는다. 재 본 것이다 (2026-08-23).

| | |
|---|---|
| Node `fetch` | **200** · 27,169바이트 · 192ms |

네이버는 TLS 지문을 봐서 Node 의 fetch 를 429 로 밀어냈고, 그래서 거기서는 크롬 창을
띄워 그 안에서 지켜보는 것이 기본 길이 됐다. 롯데온은 거기까지 보지 않는다. 그래서 이
판은 **bnkr 쪽과 같은 모양**이다 — 조회는 HTTP 로 여럿을 동시에, 누르는 것만 크롬으로.

재고는 상품 페이지 `<head>` 의 schema.org ld+json 을 본다. 서버가 그려 주는 것이라
자바스크립트를 돌리지 않아도 읽힌다.

```json
{"@type":"Product","name":"포켓몬 메가레쿠자","sku":"LM4904810155652",
 "offers":{"price":"22500","availability":"https://schema.org/InStock"}}
```

화면의 버튼(`바로 구매하기`·`품절`)은 자바스크립트가 그린다. 서버가 준 HTML 에는 없다.
그래서 HTTP 로 볼 때 믿을 것은 ld+json 뿐이고, 화면을 보고 판단하는 길은 크롬 창에서만
쓴다.

## 쓰는 법

**`node/` 안에서** 부른다.

```bat
npm install
npm run build

npm run lotte:cookie     :: 클립보드의 Cookie 줄을 설정에 저장
npm run lotte:whoami     :: 빌려온 세션이 살아 있는지
npm run lotte            :: 지켜보다가 열리면 산다
```

상품 주소를 복사해 두고 곧장 지켜보는 것이 가장 짧다.

```bat
npm run lotte:link
```

윈도우에서는 `..\run-lotte-buy-node.bat` 이 빌드까지 해 주고, 뒤에 붙인 옵션을 그대로 넘긴다.

| | |
|---|---|
| `--once` / `--dry-run` | 한 번만 / 사지 않고 본다 |
| `--status` | 대상 상품의 현재 재고만 |
| `--probe [URL]` | 상품 페이지를 뜯어보고 `lotteon-page-dump.txt` 에 남긴다 |
| `--whoami` | 빌려온 세션이 살아 있는지 |
| `--add URL …` | 살 상품을 넣는다 |
| `--link [URL]` | 클립보드의 주소를 이번 실행의 대상으로 삼고 곧장 감시 |
| `--buy [URL]` | 지금 바로 산다, 결제창까지 |
| `--dump-pay [URL]` | `--buy` 와 같되, **결제창에 무엇이 있었는지 받아 적는다** |
| `--action open\|agree\|submit` | 이번만 어디까지 갈지 |
| `--reset` | 산 기록을 지운다 |
| `--cookie [쿠키]` | Cookie 줄을 저장 (값 없이 = 클립보드) |

## 어디까지 가나 — `order_action`

| | |
|---|---|
| `"submit"` (기본) | 필수 동의 → 결제하기 → **PG 결제창을 띄우고 멈춘다** |
| `"agree"` | 주문서에서 필수 동의까지 하고 멈춘다 |
| `"open"` | 주문서를 열어 두고 멈춘다 |

**필수 동의만 체크한다.** 보이는 체크박스를 다 누르면 광고 수신 동의까지 켜진다. 그래서
조건을 좁혔다 — 아직 안 켜져 있고, 옆에 적힌 글에 "필수" 가 있고, "선택"·"광고"·
"마케팅"·"수신"·"혜택" 이 없는 것만 누른다.

## 결제수단 — `pay_method`

기본값이 **L.PAY 간편결제**다.

```json
"pay_method": ["간편결제"],
"pay_method_mark": "L.PAY|L.pay|엘페이"
```

**왜 "L.PAY" 가 아니라 "간편결제" 인가.** 처음에는 `L.PAY` 로 적어 뒀다가 틀렸다.
사이트 자바스크립트의 결제수단 표(`PY_MNS_CD`)에서 그 이름을 읽었는데, 그 표는
**결제가 끝난 뒤 무엇으로 냈는지 적는 이름**이지 고르는 화면의 이름이 아니었다.

주문서를 받아 적어 보니(`/p/order/orderSheet/one/payments`) 결제수단은 탭 아홉 개다.

```
간편결제 · 신용카드 · 충전결제 · 퀵계좌이체 ·
카카오페이 · 네이버페이 · 토스페이 · 삼성페이 · 온누리상품권
```

카카오·네이버·토스·삼성은 각자 제 이름의 탭을 갖고 있는데 **롯데 것만 제 이름 대신
"간편결제" 로 앉아 있다.** 표의 `11` L.PAY신용카드 · `20` L.PAY계좌 가 그것이다.

**탭을 누르고 끝내지 않는다.** 누른 뒤에 화면에 `L.PAY` 가 정말 떴는지 확인한다
(`pay_method_mark`). 탭 이름만 믿으면 "간편결제" 가 딴 것을 가리키게 바뀌었을 때
조용히 엉뚱한 수단으로 결제창을 띄운다. 안 보이면 **결제하기를 누르지 않는다** —
주문서는 열어 둔 채 멈추고 무엇을 못 찾았는지 적어 준다.

### 탭을 누른 것으로 끝나지 않는다 — 카드를 골라야 한다

간편결제 탭 안은 이렇게 생겼다.

```
input[radio]#lpayCard   "L.PAY 카드"      input[radio]#lpayBank "L.PAY 계좌"
label "카드선택"   input[search]#lpayCardSelect.vs__search    button "+카드 추가"
label "할부선택"   input[search]#selectLCard2.vs__search
```

`vs__` 는 vue-select 다. **목록은 눌러야 열리고 열린 뒤에만 DOM 에 있다** — 글자로 찾는
보통 방법으로는 안 잡힌다. 그래서 열고, 뭐가 있는지 읽고, 고른다.

```json
"pay_method": ["간편결제", "L.PAY 카드"],
"pay_card": ""
```

`pay_card` 를 비워 두면 **등록된 카드가 하나일 때만** 그것을 고른다. 여러 개인데 안
적어 뒀으면 고르지 않고 목록을 적어 준다 — 남의 카드를 우리가 정할 일이 아니다.
이름의 일부만 적으면 된다 (`"롯데"`, `"1234"`).

카드를 안 고르고 결제하기를 누르면 사이트가 alert 로 막는다. 그래서 여기서 멈춘다.

## 필수 동의

보이는 체크박스를 다 누르면 안 된다. 실제 주문서에 이런 것들이 있었다 — 둘 다
**건드리면 안 되는 것**이다.

```
input[checkbox]#safeNumber_0   "안심번호 사용"
input[checkbox]#defaultPay     "이 결제수단을 다음에도 사용"
```

그래서 좁혔다 — 아직 안 켜져 있고, 옆에 적힌 글에 **"필수" 나 "결제에 동의"** 가 있고,
"선택"·"광고"·"마케팅"·"수신"·"혜택" 이 없는 것만 누른다.

`"결제에 동의"` 를 넣은 것도 받아 적고 나서다. 롯데온의 결제 동의 문구에는 **"필수" 가
안 붙어 있다.**

```
label "위 내용을 확인하였으며 결제에 동의합니다."
```

"필수" 만 보게 해 뒀다가 이걸 놓쳤다. 다만 이게 체크박스가 아니라 그냥 안내문일 수도
있다(그렇게 보인다) — 눌러야 하는 것이었다면 사이트가 결제하기에서 alert 로 막고,
그게 사유로 올라온다.

현금영수증(`소득공제용`·`지출증빙용`·`신청안함`)과 L.POINT 사용 금액은 건드리지 않는다.
사람이 정할 것이다.

## 처음 한 번은 `--dump-pay` 로

**이 프로그램을 만들 때 주문서와 결제창을 못 봤다.** 로그인은 사람이 하는 것이라
계정으로 들어가 볼 수 없었다. 그래서 갈라 적어 둔다.

| | |
|---|---|
| 확인함 | 상품 페이지를 열고 수량을 올려 `바로 구매하기` 를 누르는 것까지. 게스트로 한 번 돌려 봤다 — 눌린 것은 `button.hasBgColor.bgColorRed.sizeLarge.alignLeft "바로 구매하기"` 였고(장바구니도 선물하기도 아니다), 그다음 로그인으로 튕긴 것을 코드가 알아봤다 |
| 확인함 | 재고·가격·이름(ld+json), 세션이 살았는지 묻는 자리, 주문서의 주소 모양 |
| 확인함 | 주문서 화면. `--dump-pay` 로 받아 적었다 — 결제수단 탭 아홉 개, 동의 문구, `button.hasBgColor.bgColorDarkBlack "결제하기"` |
| 확인함 | 간편결제 탭 안 — `#lpayCard`/`#lpayBank` 라디오, vue-select 카드선택 칸, 할부선택 칸 |
| **못 봄** | **결제창.** 카드를 안 고른 채 결제하기를 눌러 사이트가 막았다. 아직 거기까지 못 갔다 |

못 본 자리는 **글자로** 찾는다(`결제하기`·`주문서`·`필수`). 글자는 사이트가 바꿔도
사람이 읽고 고칠 수 있다. 그래도 처음 한 번은 본 것으로 고치는 편이 낫다.

```bat
npm run lotte -- --dump-pay
```

`lotteon-pg-dump.txt` 에 프레임마다 무엇이 있었는지 적힌다. 그걸 보고
`src/lotte/browser.ts` 의 `PAY_TEXTS`·`ORDER_TEXTS`·`AGREE_JS` 를 고치면 된다.
**이 파일이 이미 세 번 일했다** — 결제수단 탭 이름, 동의 문구, 그리고 간편결제 안의
카드 고르는 칸이 전부 여기서 나왔다. 짐작으로 고쳤으면 세 번 다 틀렸을 것이다.
**사람 정보는 지우고 적는다** — 이름·연락처·주소·카드번호는 가려서 남기고,
라디오·체크박스의 value 는 남긴다(무엇을 고를 수 있는지 말해 주는 표라서).

받아 적기는 기본으로도 돈다. 다만 **어긋난 것이 있을 때만** 한다(`pg_dump`) — 잘 간
판에서까지 200KB 짜리 마크업을 긁어 오느라 몇 초를 치를 이유가 없다.

## 본판을 안 건드리고 시험하기 — 테스트 판

`src/lotte-test/` 에 통째로 베낀 판이 있다. 하는 일은 같고 **쓰는 파일만 다르다.**

```bat
npm run lotte:test            :: 지켜보다가 열리면 산다
npm run lotte:test:dump       :: 지금 사고 결제창을 받아 적는다
npm run lotte:test:whoami     :: 빌려온 세션이 살아 있는지
```

윈도우에서는 `..un-lotte-test-node.bat`.

| 본판 | 테스트 판 |
|---|---|
| `lotteon_buy_config.json` | `lotteon_test_config.json` |
| `lotteon_buy_state.json` | `lotteon_test_state.json` |
| `lotteon-buy.log` | `lotteon-test-buy.log` |
| `lotteon-pg-dump.txt` | `lotteon-test-pg-dump.txt` |
| `lotteon-page-dump.txt` | `lotteon-test-page-dump.txt` |

**왜 가르나.** 같은 파일을 쓰면 시험 삼아 돌린 한 판이 본판의 산 기록·로그·결제창
받아쓰기를 덮는다. 실제로 그렇게 덮여서 결제창을 받아 적을 유일한 기회를 날린 적이 있다.

**설정은 처음 켤 때 본판 것을 베껴 온다.** 감시 대상과 웹훅을 다시 적게 하지 않는다.
어디서 베껴 왔는지는 그때 화면에 적는다.

**쿠키만은 두 벌 관리하지 않는다.** 테스트 설정의 `cookie` 는 비워 둔 채로 두고, 매번
본판에서 빌려 온다. 베껴 두면 그 순간부터 두 벌이 되고, 본판에 쿠키를 새로 넣어도
이쪽은 낡은 것을 붙들고 있게 된다 — 그걸 알아채는 자리는 하필 재고가 열린 순간이다.

**설정은 갈라져 있으니 마음껏 고쳐도 된다.** 결제수단을 바꿔 보려면 테스트 설정의
`pay_method` 한 줄이면 된다. 주문서에서 받아 적은 탭 이름들이다.

```json
"pay_method": ["카카오페이"]
"pay_method": ["네이버페이"]
"pay_method": ["신용카드"]
```

`간편결제` · `신용카드` · `충전결제` · `퀵계좌이체` · `카카오페이` · `네이버페이` ·
`토스페이` · `삼성페이` · `온누리상품권` 아홉 개다. 간편결제 말고 다른 것을 고를 때는
`pay_method_mark` 도 같이 고치거나 비워 둬야 한다 — 그건 "L.PAY 가 보이는지" 를 보는 것이라
다른 수단에서는 안 보이는 게 정상이다.

**bnkr 쪽 테스트 판(`src/bnkr-test/`)과 같은 짜임이다.** 다른 것이 하나 있다 — bnkr 판은
`ui`·`util`·`log`·`browser` 를 제 것으로 갖고 있어 그것까지 통째로 베꼈지만, 롯데온 판은
그 조각들을 원래 bnkr 것에서 빌려 쓴다. 그래서 여기서도 그대로 빌려 쓰고, 롯데온 판이
제 것으로 가진 **열 개 파일만** 베꼈다.

### 테스트 판에만 있는 것 — 대기열과 크롬 띄워 두기 (2026-10-03)

데스크톱 앱이 돌리는 것이 테스트 판이라 여기에 먼저 넣었다. `tracer.ts` · `warm.ts` 두 파일이다.

**대기열(TRACER).** 붐비면 상품 페이지 대신 "현재 N명의 고객님이 대기중이에요" 가 오고, 차례가
오면 화면이 스스로 상품 페이지로 넘어간다. 순번은 그 크롬의 쿠키(`wcCookie`)에 붙어 있다 —
**창을 닫거나 새 크롬을 띄우면 맨 뒤다.** MEGA 30th 예약판매 날 예전 코드가 20초마다 그렇게
해서 세 번 맨 뒤에 섰다. 지금은 대기 화면이면 그 창에서 `queue_wait_seconds`(300초)까지 기다리고,
다시 할 때도 같은 창을 쓴다. 대기열에서 진 것은 품절로 진 것처럼 쉬지 않는다.

**크롬 띄워 두기.** 감시를 켜면 상품마다 크롬 창 하나를 상품 페이지에 세워 둔다. 열리면 새로
고침만 하고 바로 누른다 — 크롬을 띄우는 3~4초가 빠진다. **대기열이 서 있으면 켤 때 그 창에서 한 번
줄을 선다.** 열리는 시각을 아는 상품이면 열린 뒤 `queue_wait_seconds` 까지 그 줄에서 기다린다. 열리는
순간 둘레(1분 전 ~ 2분 뒤)는 평소 걸음이어도 1초 걸음으로 보고, 열리는 그 초에 맞춰 깬다.

예전에는 열리기 30분 전부터 대기열을 살피다가 열리기 60초 전에 통과하도록 줄 설 때를 맞췄다
(`warm_window_minutes` · `warm_lead_seconds`). 통과한 자리는 ~30초뿐이고(10-10 실측) 줄 속도는 날마다
달라서(10-17 은 열리기 8분 전부터 0.5명/초) 맞지 않았다. 2026-10-21 에 없앴다 — 두 칸은 이제 읽지 않는다.
**언제 켤지는 사람이 정한다.** 데스크톱 태스크 창의 "대기열 보기" 가 줄 길이를 보여 준다.

- 창은 상품마다 **하나**다. 줄을 여러 번 서지 않는다. 주문 API 를 바로 부르는 식으로 줄을
  건너뛰지도 않는다 — 대기열 서버가 아이피째 막을 수 있다("서비스 접속이 차단되었어요").
- 멈추면 상품 페이지·대기 화면에 서 있는 창만 닫는다. 주문서·결제창까지 간 창은 남는다.
- 끄려면 `warm_browser: false`. `--dry-run`(모니터)·`--once` 는 띄우지 않는다.
- **줄에서 나오지 않는다.** 태스크를 멈추면 대기 화면에 서 있던 창이 닫혀 자리를 잃는다. 다시 켜면 맨 뒤다.

## 쓰는 파일

파이썬 짝이 없으므로 나눠 쓰는 파일도 없다. 이름만 다른 판과 맞춰 프로젝트 뿌리에 둔다.

| | |
|---|---|
| `lotteon_buy_config.json` | 설정 (쿠키·상품·웹훅) |
| `lotteon_buy_state.json` | 산 기록. 켤 때마다 같은 걸 또 사지 않으려는 것 |
| `lotteon-buy.log` | 전부 적는 곳 |
| `lotteon-page-dump.txt` | `--probe` 가 찾은 ld+json |
| `lotteon-pg-dump.txt` | `--dump-pay` 가 적은 결제창 |

웹훅(`discord_webhook_url`)을 안 적으면 `bnkr_buy_config.json` 것을 빌려 쓴다. 빌려
쓰기만 하고 베껴 두지는 않는다.

## 알아 둘 것

- **수량 한도가 상품마다 다르다.** 수량 스피너에 `aria-valuemax` 로 적혀 있다(확인한
  상품은 5였다). 그 값을 먼저 읽고 거기까지만 올린다 — 넘겨 누르면 사이트가 alert 로
  막고, 그 alert 를 닫지 않으면 이후 조작이 전부 막힌다.
- **수량으로는 사기 전에 막지 못한다.** ld+json 은 "있다/없다" 만 말하고 몇 개인지는
  안 알려 준다. 재고보다 많이 담으려 하면 사이트가 alert 로 막고, 그때 사유로 올라온다.
- **품절 표시를 아직 못 봤다.** `InStock` 만 확인했다. 품절인 상품에서 무엇이 오는지는
  `product.ts` 의 표에 짐작으로 적어 뒀고, 모르는 값이 오면 **품절로 넘기지 않고 그렇게
  말한다** — 품절로 치면 재고가 열린 걸 놓치고, 구매가능으로 치면 없는 버튼을 누르러 간다.
- **처음 본 상품은 사지 않는다**(`buy_on_restock_only`). 품절 → 구매가능 으로 바뀌는
  순간에만 산다. 설정을 잘못 써 놓고 실행했을 때 곧장 결제창까지 가버리는 사고가
  여기서 막힌다. 지금 사려면 `--buy` 다.
- **한 번 시도한 상품은 `cooldown_minutes`(기본 30분) 동안 쉰다.** 같은 상품을 몇 초마다
  두드려 주문서를 쌓지 않으려는 것인데, **터진 판도 시도로 센다** — 크롬 창이 사라져
  실패한 뒤 30분을 조용히 쉬는 일이 실제로 있었다. 지금은 왜 쉬는지와 얼마나 남았는지를
  말해 준다. 기록을 지우려면 `--reset`, 안 쉬게 하려면 `cooldown_minutes: 0`.
  `--buy` 와 `--dump-pay` 는 사람이 지금 부른 명령이라 쉬는 것과 상관없이 간다.
- **건너뛸 때 조용히 넘어가지 않는다.** 기다리는 줄에 지금 무엇을 보고 있는지 적는다
  (`잉어킹 — 계속 판매 중 (재입고를 기다립니다)`). "지켜보는 중" 만 떠 있으면 잘 돌고
  있을 때와 아무것도 안 할 때가 똑같이 보인다 — 이 프로젝트에서 제일 나쁜 상태다.
- **누른 것과 결제창이 뜬 것은 다르다.** 여기서 데었다 — 눌리기만 하면 "submitted" 로
  적었더니, 사이트가 alert 로 막은 판을 "결제창까지 띄웠습니다" 라고 보고하고 그 alert
  문구를 묻어 버렸다. 지금은 창을 봤거나 신호를 못 본 경우만 갔다고 하고, 막힌 것은
  `agreed` 에서 멈춘 것으로 적는다.
- **`--dry-run` 은 크롬을 안 띄운다.** 쿠키도 안 싣고 재고만 본다.
- **크롬 창이 사라져도 감시는 안 죽는다.** 2026-08-23 에 여기서 데었다 — 주문서에
  도착한 6초 뒤 창이 없어져 셀레니움이 `invalid session id` 를 던졌고, 그게 감시를
  통째로 끝냈다. 감시가 죽은 것보다 나빴던 것은 **받아적기를 못 한 것**이다. 결제창은
  아무 때나 띄워 볼 수 있는 화면이 아니라, 그 판이 셀렉터를 고칠 유일한 기회였다.
  지금은 그 자리에서 잡아 적고 다음 바퀴로 넘어간다.

## 무엇이 어디에 있나

`node/src/lotte/` 아래다. 화면(`ui.ts`)·잔손질(`util.ts`)과, 글자로 눌러야 할 것을 찾고
누르고 프레임을 타는 조각(`browser.ts` 의 `FIND_TEXT_JS`·`press`·`reacted`·`settled`·
`descend`·`framePaths`)은 **bnkr 판 것을 빌려 쓴다.** 네이버 판이 같은 것을 하고 있다 —
그 조각들은 결제창에서 여러 번 틀려 가며 다듬은 것이라, 사이트마다 다시 쓰는 것보다
빌려 쓰는 편이 낫다.

| | |
|---|---|
| `index.ts` | 명령줄 |
| `config.ts` | 설정·상태·로그 파일 자리 |
| `targets.ts` | 상품 주소 알아보기 (`LM…` 과 `sitmNo`) |
| `http.ts` | 세션·로그인 확인·429 백오프 |
| `product.ts` | ld+json 에서 재고·가격·이름 |
| `browser.ts` | 크롬. 수량 · 바로 구매하기 · 주문서 확인 · 필수 동의 · 결제하기 · 결제창 받아적기 |
| `order.ts` | 주문서까지 데려다 놓고 시킨 데까지 누르기 |
| `watch.ts` | 감시 루프 · 설정 실시간 반영 |
| `commands.ts` | 한 번 부르고 끝나는 것들 (`--status`·`--probe`·`--buy`…) |
| `notify.ts` | 디스코드 |
