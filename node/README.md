# bnkr_buy — Node.js / TypeScript 판

`bnkr_buy.py` 를 통째로 옮긴 것이다. 하는 일도, 판단하는 방식도, 화면에 찍히는 말도 같다.

> **이 저장소는 bnkr(반다이남코코리아몰) 판만 담는다.**
> 같은 작업 폴더에는 네이버 판(`src/naver/`)과 롯데온 판(`src/lotte/`)도 있는데, 그 둘은
> `.gitignore` 로 빼 두었다 — 화면·로그·크롬을 다루는 조각을 여기 것에서 빌려 쓸 뿐
> 나머지는 각자 폴더 안에 있어서, 빼도 이쪽은 그대로 선다.
> 그래서 `package.json` 에 `naver:*` · `lotte:*` 스크립트가 남아 있다. 이 저장소만
> 받아서는 그 스크립트들이 돌지 않는다.

```
지켜보기(초 단위) → 구매 가능 감지 → 장바구니 담기 → 디스코드 알림
                  → 주문서 열기 → 필수 동의 → 결제하기 → 결제창 QR 을 폰으로 → [사람] 결제
```

**결제 확정은 사람이 누른다.** 카드 인증도 간편결제 비밀번호도 이 프로그램이 다루지
않는다. 로그인도 자동화하지 않는다(reCAPTCHA v3) — 브라우저에서 로그인한 세션 쿠키를
빌려 쓴다.

## 쓰는 법

**`node/` 안에서** 부른다. 경로를 앞에 또 붙이면(`node node/dist/index.js`) 없는 파일을
찾게 된다 — 여기서 dist 는 이미 `node/` 아래다.

```bat
npm install
npm run build

npm run cookie     :: 클립보드의 Cookie 줄을 설정에 저장 (= node dist/index.js --cookie)
npm run whoami     :: 세션이 살아 있는지
npm run watch      :: 지켜보다가 열리면 담는다
```

다른 옵션은 `node dist/index.js --once` 처럼 곧장 부르거나 `npm start -- --once` 로 준다.
윈도우에서는 `..\run-bnkr-buy-node.bat` 이 빌드까지 해 주고, 뒤에 붙인 옵션을 그대로 넘긴다.

명령은 파이썬 판과 하나씩 짝이 맞는다.

| | |
|---|---|
| `--once` | 한 번만 확인하고 종료 |
| `--dry-run` | 담지 않고 무엇을 담을지만 |
| `--status` / `--cart-list` / `--whoami` | 재고 · 장바구니 · 세션 확인 |
| `--find 말 …` | 이름으로 목록을 훑어 gno 찾기 (로그인 불필요) |
| `--add gno\|URL …` | 담을 상품을 설정에 추가 |
| `--cart gno` / `--buy gno` / `--ea N` | 지금 바로 담기 (`--buy` 는 주문서까지) |
| `--open [ADD\|DIRECT\|GIFT]` | 담지 않고 주문서만 열어 보기 |
| `--action open\|agree\|submit` | 주문서에서 어디까지 누를지 (이번만) |
| `--reset` | 담은 기록 지우기 |

`npm run bench` 는 파이썬 판과 같은 일(재고 조회·목록 훑기·상세 파싱)에 걸리는 시간을 잰다.

## 한 번에 여럿 보기 — `max_concurrency`

설정에 `"max_concurrency": 4` (기본값)를 둔다. **조회와 목록 훑기에만 걸린다.**

감시 대상이 여럿일 때 한 바퀴가 짧아진다. 20개를 재 보면:

| | 한 바퀴 | 개당 |
|---|---|---|
| `1` (순차, 파이썬 판과 같음) | 450ms | 22.5ms |
| `4` | 137ms | 6.8ms |
| `8` | 73ms | 3.6ms |

**담기·주문서·결제창은 어떤 값을 주든 한 줄로 간다.** 거기를 병렬로 만들 이유가 없다 —
계정이 하나고, 이 사이트의 수량 제한도 계정당이라 같은 것을 여럿이 두드려 봐야 얻는 게
없다. 잘못 건드리면 같은 상품을 두 번 담는 쪽으로 간다. 크롬도 한 프로필에 한 창이다.

값을 올린다고 계속 빨라지지도 않는다. 한 아이피에서 **동시에** 두드리는 횟수이기도 하다.
감시 대상이 이 수보다 적으면 아무것도 달라지지 않는다.

## 네이버페이 테스트 판 — `src/bnkr-test/`

본판을 통째로 베낀 복사본이다. **다른 것은 둘뿐이다.**

1. 결제창에서 **네이버페이**로 간다. 본판은 카카오페이 카톡결제로 가 있다.
2. 설정·상태·로그·덤프를 `bnkr_test_*` 로 따로 쓴다. **쿠키만 본판 것을 빌려 온다.**

```bat
npm run npay          :: 지켜보다가 열리면 담는다 (= node dist/bnkr-test/index.js)
npm run npay:whoami   :: 세션이 살아 있는지
```

윈도우에서는 `..\run-bnkr-test-node.bat`. 옵션은 본판과 하나도 다르지 않다.

**왜 복사본인가.** 결제창은 아무 때나 띄워 볼 수 있는 화면이 아니다 — 다음 기회는 재고가
정해 준다. 수단을 바꿔 시험하려면 본판 설정의 `pg_clicks` 를 고쳐 가며 돌리는 수밖에
없었는데, 그러다 보면 지금 본판이 카카오페이로 되어 있는지 네이버페이로 되어 있는지가
헷갈리고, 정작 재고가 열린 날 엉뚱한 창이 뜬다. 시험은 여기서 하고 본판은 건드리지 않는다.

**누르는 순서.** 네이버페이에 물려 둔 **카드**로 낸다.

```
1. 이용약관에 동의해 주세요   →  동의합니다 → 다음
2. 결제 수단을 선택해 주세요  →  네이버페이 → 다음
3. 네이버페이 창             →  결제하기
```

1·2·4번째는 2026-08-17 에 실제로 통과한 그대로다(`bnkr-buy.log`). 3번째 자리에 그날 들어
있던 것은 `포인트`(label `"네이버페이포인트"`)였고, **거기만 `네이버페이` 로 바꿨다.** 그
목록에는 둘이 나란히 있다 — 포인트로 내는 것과 카드로 내는 것이 PG 쪽에서 아예 다른
수단이다. 포인트로 돌리려면 `pg_clicks` 의 그 자리를 `포인트` 로 되돌린다.

**글자가 겹치는 것을 알고 쓴다.** 글자 찾기는 품고 있는 것도 잡으므로(찾는 글자 + 10자
까지) `네이버페이` 는 "네이버페이포인트" 에도 걸린다. 그래도 되는 이유는 고르는 순서에
있다 — 누를 수 있는 것 먼저, **글자가 정확히 같은 것 먼저**, 짧은 것 먼저다. 목록의 두
줄은 생김새가 같으니(둘 다 라디오를 label 로 감싼 꼴) 정확히 같은 쪽이 이긴다. 카카오페이가
label `"카카오페이"` 로 정확히 잡혔던 것과 같은 자리다.

**무엇이 눌렸는지는 로그가 말해 준다.** 이 줄의 따옴표 안을 본다.

```
결제창에서 '네이버페이' 를 눌렀습니다 — label "네이버페이"        ← 카드 (맞다)
결제창에서 '네이버페이' 를 눌렀습니다 — label "네이버페이포인트"   ← 포인트 (틀렸다)
```

뒤엣것이 찍혔다면 그 화면에 네이버페이 줄이 없었다는 뜻이다. 그때 받아 적은
`bnkr-test-pg-dump.txt` 에 그 화면의 진짜 글자가 남아 있으니 그것으로 고친다.

마지막 `결제하기` 는 네이버페이 창의 "동의하고 결제하기" 다. **여기서 결제가 확정되지
않는다** — 그다음에 오는 간편결제 비밀번호·인증은 사람의 자리다. 카드가 여럿이면 그 창에서
카드를 고르는 단계가 하나 더 있을 수 있는데 **아직 못 본 화면이다.** 안 본 화면의 글자를
지어내 적으면 엉뚱한 것을 누르므로, 보고 나서 적는다. 승인 뒤에 한 번 더 나오는 확인
화면(`pg_finish`)도 같은 이유로 비워 뒀다.

**네이버 로그인을 미리 해 둔다.** 네이버페이는 결제창 안에서 네이버에 로그인해야 하는데,
재고가 열린 뒤에 시작하면 늦다 — 그 순간에 캡차라도 뜨면 그 판은 끝이다. 그래서 이 판은
`prelogin_url` 을 네이버 로그인 페이지로 두고, 지켜보는 동안 창을 띄워 사람을 기다린다.
**로그인은 사람이 한다.**

**처음 켤 때** `bnkr_test_config.json` 이 없으면 본판 설정을 베껴서 만든다 — 감시 대상과
웹훅을 다시 적게 하지 않는다. 베낄 때 결제와 얽힌 세 가지(`pg_clicks`·`pg_finish`·
`prelogin_url`)만 갈아 끼우고, **쿠키는 일부러 안 베낀다.** 베껴 두면 그 순간부터 두 벌이
되고 본판을 갱신해도 이쪽은 낡은 것을 붙들게 된다. 비워 두면 켤 때마다 본판에서 빌려 온다.
한 번만 만들고 그 뒤로는 손대지 않으니, 테스트 설정을 고쳐 둔 것이 다음에 켤 때 도로
덮이지는 않는다.

디스코드 알림에는 꼬리말에 `(네이버페이 테스트)` 가 붙는다. 본판과 같은 채널로 가는데
받은 쪽에서 어느 쪽이 보낸 것인지 알 길이 없어서다.

## 파이썬 판과 나눠 쓰는 것

설정(`bnkr_buy_config.json`) · 상태(`bnkr_buy_state.json`) · 로그(`bnkr-buy.log`) 는
**같은 파일을 쓴다.** 쿠키를 두 벌 관리하게 만들지 않으려는 것이고, 담은 기록도
마찬가지다 — 한쪽으로 담아 놓고 다른 쪽으로 켰을 때 또 담으면 두 개가 된다.

그래서 **둘을 동시에 돌리지 않는다.** 같은 상태 파일에 번갈아 쓰면 마지막에 쓴 쪽만 남는다.

## 통합 태스크 러너 — `src/task/`

**bnkr-test 와 lotte-test 를 한 프로그램에서 동시에 돌리는 판**이 따로 있다.
감시 대상을 `task_config.json` 의 태스크 목록으로 관리하고, 사이버슐 같은 태스크
표 화면에서 어느 태스크가 무슨 상태인지 본다. 자세한 것은 [`README-task.md`](README-task.md).

```bat
..\run-cyber-node.bat            :: 두 사이트를 동시에 지켜본다
..\run-cyber-node.bat list       :: 태스크 표
..\run-cyber-node.bat add --site bnkr|lotte 상품
```

각 사이트 루프는 이 저장소의 기존 판(bnkr-test / lotte-test) 코드를 그대로 쓰므로
감시·담기·주문서·결제 판단과 **요청 속도·동시성도 그대로**다. 두 루프가 한 프로세스에서
나란히 돌 뿐이다(I/O 바운드라 서로를 기다리지 않는다).

## 파이썬 판과 다른 것

- **TLS 지문을 흉내내지 않는다.** 파이썬 쪽은 `curl_cffi` 가 크롬인 척하지만, Node 의
  fetch 는 그런 것이 없다. 헤더는 같게 보내고 지문은 Node 것 그대로다. 이 사이트는
  지금까지 거기까지 보지 않는다.
- **쿠키 항아리가 단순하다.** 파이썬 쪽은 같은 이름이 도메인만 달리해 둘 남는 문제가
  있어 낡은 쪽을 골라 버리는 코드가 따로 있는데(`drop_stale_cookies`), 여기 항아리는
  이름 하나에 값 하나뿐이라 사이트가 새로 내주면 그 자리에서 덮인다.
- **크롬은 `selenium-webdriver` 로 몬다.** 크롬드라이버는 셀레니움이 알아서 받는다.
  창은 `detach` 로 남기므로 프로그램이 끝나도 주문서는 그대로 떠 있다.
- 클립보드는 `Get-Clipboard`(윈도우) · `pbpaste` · `xclip` 로 읽는다.

## 무엇이 어디에 있나

| | |
|---|---|
| `index.ts` | 명령줄. 파이썬 판의 `parse_args`·`main` |
| `watch.ts` | 지켜보기·담기 판단·설정 실시간 반영 |
| `browser.ts` | 크롬. 주문서 확인 · 필수 동의 · 결제창 클릭 · 화면 찍기 (`bnkr_browser.py`) |
| `landing.ts` | 주문서 열기·결제창 화면 보내기·결제 완료 지켜보기 |
| `site.ts` | 사이트가 쓰는 엔드포인트들 (재고·상세·담기·로그인) |
| `list.ts` | 목록 한 장 읽기 (`bnkr_stock.py` 의 훑어보는 부분) |
| `cart.ts` | 담기·수량 제한 대응·마지막 관문 |
| `notify.ts` | 디스코드 |
| `queue.ts` | 대기열 판정 (`bnkr_queue.py`) |
| `ui.ts` · `log.ts` | 화면과 로그 (`bnkr_console.py`) |
| `bench.ts` | 시간 재기 |

창 안에서 도는 자바스크립트 조각들은 파이썬 판의 것을 글자 그대로 가져왔다. 그것들이
왜 그렇게 생겼는지는 하나하나 데어 가며 알아낸 것이라, 옮기면서 손대지 않았다.
