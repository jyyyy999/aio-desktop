# naver_buy — Node.js / TypeScript 판

`naver_buy.py` 를 옮긴 것이다. 하는 일도, 멈추는 자리도 같다.

```
지켜보기(초 단위) → 구매 가능 감지 → 구매하기 클릭 → 구매 레이어에서 바로구매
                  → 네이버페이 주문서 → 디스코드 알림 → [사람] 결제
```

**결제 확정은 사람이 누른다.** 주문서까지만 간다 — 네이버는 결제가 끝나야 재고를 깎으므로,
주문서를 열어 둔다고 물건을 잡아 두는 것이 아니다. 로그인도 자동화하지 않는다(캡차·기기
등록). 브라우저에서 로그인한 세션 쿠키를 빌려 쓴다(신분은 `NID_AUT`·`NID_SES` 가 진다).

---

## 먼저 알아야 할 것 — **Node 로는 HTTP 조회가 안 된다**

네이버는 Node 의 요청을 밀어낸다. 확인한 것이다 (2026-08-23, 같은 주소·같은 시각).

| | |
|---|---|
| `python naver_buy.py --probe` | **200** · 179,999바이트 |
| Node `fetch` (헤더 다섯 벌을 바꿔 가며) | 429 · 23,585바이트 |
| Node `http2` (맨몸 · 크롬 헤더) | 429 · 23,585바이트 |
| `curl.exe` | 429 · 23,585바이트 |

헤더로는 안 갈린다. UA 를 빼도, `sec-fetch` 를 한 벌 붙여도, HTTP/2 로 물어도 같다.
갈리는 것은 **TLS 지문**이다 — 파이썬 쪽은 `curl_cffi` 가 크롬의 ClientHello 를 그대로
흉내내지만(`impersonate="chrome"`), Node 의 fetch 에는 그런 것이 없다.

지문을 속이려 들지 않는다. 대신 **진짜 크롬을 쓴다.**

```bat
npm run naver:window -- https://smartstore.naver.com/<스토어>/products/<번호>
```

이 길은 원래 캡차 벽이 있는 스마트스토어 상품 때문에 파이썬 판에 있던 것인데
(`--watch-browser`), Node 에서는 이게 **기본 길**이다. 창에 뜬 상품 페이지에서
`window.__PRELOADED_STATE__` 를 읽으므로 지문도 캡차도 문제가 되지 않는다.

`bnkr` 쪽은 이 벽이 없다. 같은 Node 인데 갈리는 이유는 사이트가 다르기 때문이다 —
반다이남코몰은 TLS 지문까지 보지 않는다.

## 쓰는 법

**`node/` 안에서** 부른다.

```bat
npm install
npm run build

npm run naver:cookie     :: 클립보드의 Cookie 줄을 설정에 저장
npm run naver:whoami     :: 빌려온 세션이 살아 있는지 (이건 Node 로도 된다)
npm run naver:window     :: 크롬 창을 띄워 그 안에서 지켜본다  ← 이게 기본 길이다
```

상품 주소를 복사해 두고 곧장 지켜보는 것이 가장 짧다. `--link` 가 대상을 그 하나로
바꾸고, `--watch-browser` 가 그 대상을 창에서 본다.

```bat
npm run naver -- --link --watch-browser
```

윈도우에서는 `..\run-naver-buy-node.bat` 이 빌드까지 해 주고, 뒤에 붙인 옵션을 그대로 넘긴다.

명령은 파이썬 판과 하나씩 짝이 맞는다.

| | | Node 에서 |
|---|---|---|
| `--watch-browser [URL]` | 크롬 창에서 지켜본다 | **된다 (기본 길)** |
| `--buy [URL]` | 지금 바로 산다, `order_action` 이 정한 데까지 | 된다 (막히면 창으로 넘어간다) |
| `--dump-pay [URL]` | `--buy` 와 같되, 끝난 뒤 화면을 `naver-pg-dump.txt` 에 받아 적는다 | 된다 |
| `--action open\|submit` | 이번만 어디까지 갈지 (설정 파일은 안 바꾼다) | 된다 |
| `--pin [비밀번호]` | 간편결제 비밀번호 저장 (값 없이 = 클립보드, `clear` = 지우기) | 된다 |
| `--cookie [쿠키]` | Cookie 줄을 저장 (값 없이 = 클립보드) | 된다 |
| `--link [URL]` | 클립보드의 주소를 대상으로 삼는다 | 된다 (`--watch-browser` 와 함께 쓴다) |
| `--add URL …` | 살 상품을 넣는다 | 된다 |
| `--whoami` | 세션이 살아 있는지 | 된다 |
| `--reset` | 산 기록을 지운다 | 된다 |
| `--once` / `--dry-run` | 한 번만 / 사지 않고 본다 | 된다 |
| (옵션 없이) | HTTP 로 여러 상품을 지켜본다 | **막힌다** — 상품이 하나면 **알아서 크롬 창으로 넘어간다**. 여럿이면 접고 위 길을 알려 준다 |
| `--status` | 대상 상품의 재고만 | **막힌다** — 파이썬 판을 쓰세요 |
| `--probe [URL]` | 상품 페이지를 뜯어본다 | **막힌다** — 파이썬 판을 쓰세요 |

막히는 것들은 조용히 실패하지 않는다. 왜 막혔는지와 갈 길을 적고 끝낸다.

## 주문서에서 어디까지 가나 — `order_action`

| | |
|---|---|
| `"open"` (기본) | 주문서를 열어 두고 멈춘다. 결제 버튼은 사람이 누른다 |
| `"submit"` | 결제하기까지 누르고 **인증 화면 앞에서** 멈춘다. 비밀번호는 안 넣는다 |

`submit` 은 켜 두는 사람이 자기 계정을 알고 있어야 한다. 간편결제 비밀번호가 꺼진
계정이면 그 클릭이 곧 결제다 — 그래서 기본값이 아니고, 그런 일이 벌어지면 프로그램이
알아채서 크게 알린다("이 계정은 결제 인증을 묻지 않습니다").

결제하기를 누른 뒤에는 **새 창 · 새 iframe · alert · 새로 생긴 글자**를 다 보고 셋 중
하나로 적는다 — 인증 화면이 떴다 / 사이트가 막았다(alert 문구를 같이 적는다) / 신호를
못 봤다. 예전에는 주문서 본문 글자만 봐서, 인증 화면이 새 창으로 뜨면 20초를 꼬박
기다리고 "화면을 확인해 주세요" 로 끝났다.

롯데온 판에서 가져온 설정 셋 (파이썬 판에는 없다):

| | |
|---|---|
| `pg_dump` (기본 `true`) | 결제하기 뒤가 어긋나면 화면을 `naver-pg-dump.txt` 에 받아 적는다. 연락처·카드번호는 가리고, 주문서 마크업은 남기지 않는다 |
| `paid_wait_minutes` (기본 `10`) | 인증 화면까지 간 뒤 결제가 끝나기를 이만큼 지켜본다 |
| `paid_markers` | 결제 완료로 볼 글자. 주문서(`/ordersheet`)를 떠난 화면에서만 믿는다. **네이버페이 완료 화면은 아직 못 봐서** 일반 문구만 들어 있다 |

결제 완료 알림은 `discord_notify` 에 `"paid"` 를 넣어야 간다.

### 간편결제 비밀번호까지 — `pg_password`

적어 두면 인증 화면의 **비밀번호 자판을 읽어 눌러 준다** (`pin.ts`). 네이버페이는 비밀번호를
넣는 순간 결제가 끝나므로, `order_action` 이 `submit` 이면 **사람 손 없이 산다.** 기본은 비어 있다.

```bat
npm run naver -- --pin          :: 클립보드의 숫자를 저장 (값은 로그에 안 남고 자릿수만 남는다)
npm run naver -- --pin clear    :: 지운다 — submit 은 다시 인증 화면 앞에서 멈춘다
```

파일에 평문으로 남는 것이 싫으면 환경변수 `NAVER_PG_PASSWORD` 로 넘긴다.

- 자판은 매번 숫자 위치가 바뀌고 숫자가 그림(스프라이트)이다. 그림을 잘라 글꼴 투표로 읽는다.
  읽는 코드는 `bnkr-test/browser.ts` 에서 베꼈다 — 거기서 네이버페이 자판
  (`pay.naver.com/authentication/pw/check`)에 여섯 자리를 다 넣는 데까지 갔다. 고칠 일이
  생기면 **양쪽을 같이 고친다.**
- 자리마다 자판을 다시 읽고, 채워진 점 개수로 눌렸는지 확인한다.
- **틀렸으면 다시 넣지 않는다.** 몇 번 틀리면 결제가 잠긴다. 창을 두고 사람에게 넘긴다.
- 못 넣었으면(자판을 못 찾았거나 넘어가지 않았으면) 그 화면을 `naver-pg-dump.txt` 에 받아 적는다.
- **네이버 스토어 결제에서는 아직 한 번도 돌려 보지 못했다.** bnkr 쪽 결제창에서 본 자판과 같을
  것으로 보고 가져왔다.

## 켜 놓은 채로 설정 고치기

감시(옵션 없이 · `--watch-browser`)는 **바퀴마다 `naver_buy_config.json` 이 바뀌었는지 본다.**
저장하면 다음 바퀴부터 새 값으로 돈다 — 껐다 켤 필요가 없다.

| 바꾼 것 | 어떻게 되나 |
|---|---|
| `targets` (상품 주소) | HTTP 감시는 새 목록으로 본다. 크롬 창 감시는 **같은 창을 새 상품 페이지로 옮긴다** (첫 번째 상품) |
| `order_action` · `pg_password` | 다음 구매부터 적용. 바뀌면 "이제부터: …" 로 어디까지 가는지 다시 적는다 |
| 주기 · `buy_on_restock_only` · `max_price` · 알림 따위 | 다음 바퀴부터 적용 |
| `cookie` | HTTP 요청에는 바로 쓴다. **이미 띄운 크롬 창에는 예전 쿠키가 심겨 있어서** 창에서 사려면 껐다 켜야 한다 |

- 무엇이 바뀌었는지 로그에 적는다. 쿠키·비밀번호·웹훅은 칸 이름만 적고 값은 안 적는다.
- 저장하다 만(JSON 이 깨진) 파일은 읽지 않는다. 한 번 알리고 예전 설정으로 계속 돈다.
- `--action` 으로 준 값은 이번 실행 동안 파일보다 앞선다.
- `--watch-browser URL` 처럼 **주소를 직접 준 창은 targets 를 따라가지 않는다.** 그 주소가 사람의 뜻이다.
- 새로 넣은 상품에 산 기록(`done`)이 남아 있으면 건너뛴다고 적는다. 다시 사려면 `--reset`.

## 파이썬 판과 나눠 쓰는 것

설정(`naver_buy_config.json`) · 상태(`naver_buy_state.json`) · 로그(`naver-buy.log`) 는
**같은 파일을 쓴다.** 쿠키를 두 벌 관리하게 만들지 않으려는 것이고, 산 기록도
마찬가지다 — 한쪽으로 사 놓고 다른 쪽으로 켰을 때 또 사면 두 개가 된다.

그래서 **둘을 동시에 돌리지 않는다.** 같은 상태 파일에 번갈아 쓰면 마지막에 쓴 쪽만 남는다.

## 파이썬 판과 다른 것

- **HTTP 조회가 막힌다.** 위에 적었다. 이것 하나가 나머지를 다 끌고 간다.
- **벽을 만나면 재시도하지 않는다.** 캡차와 429 는 고장이 아니라 지시라, `max_attempts`
  만큼 다시 두드리면 시간만 버린다(재 보니 93초). 429 에 쉬어 보지도 않는다(backoff 없음) —
  쉬어서 열린 적이 없고, 그 31초 동안 멈춘 것처럼 보여서 사람이 꺼 버렸다.
- **한 바퀴를 통째로 못 보면 멈춘다.** 파이썬 판은 계속 돈다. Node 에서는 그게
  "지켜보는 중" 을 띄운 채 아무것도 안 지켜보는 상태가 되므로, 접고 갈 길을 알린다.
  감시 상품이 하나면 접지 않고 **그 상품을 크롬 창에서 이어서 본다**(`--watch-browser` 와 같다).
- **창에서 읽는 중에는 창을 매 바퀴 새로 받는다.** 파이썬 판은 "세션이 있으면 HTTP 로
  보는 중" 이라고 보고 창을 그대로 두는데, Node 에서는 세션이 살아 있어도 창에서 읽고
  있을 수 있다. 무엇으로 읽었는지를 보고 정한다 — 안 그러면 같은 낡은 페이지를 영원히
  다시 읽는다.
- **크롬 창 감시에서도 로그인이 살아 있는지 묻는다** (`session_check_minutes`, 기본 10분).
  끊겼으면 디스코드로 알리고 멈춘다 — 예전에는 재고가 열려 구매하기를 누르는 순간에야 알았다.
  로그인 확인(`nid.naver.com`)은 429 에 막히지 않는다.
- **`--buy` 로 산 것을 상태 파일에 적어 둔다.** 파이썬 판은 창에서 산 경우에만 적는데,
  그러면 HTTP 로 산 상품이 감시 목록에도 있을 때 다음 실행에서 또 산다.
- **클립보드는 `Get-Clipboard`(윈도우) · `pbpaste` · `xclip` 로 읽는다** (파이썬은 tkinter).
- **크롬은 `selenium-webdriver` 로 몬다.** 크롬드라이버는 셀레니움이 알아서 받는다.
  창은 `detach` 로 남기므로 프로그램이 끝나도 주문서는 그대로 떠 있다.

## 무엇이 어디에 있나

`node/src/naver/` 아래다. 화면(`ui.ts`)·잔손질(`util.ts`)과, 글자로 눌러야 할 것을 찾고
누르는 조각(`browser.ts` 의 `FIND_TEXT_JS`·`press`·`reacted`·`settled`)은 **bnkr 판 것을
빌려 쓴다.** 파이썬 쪽에서 `naver_browser.py` 가 `bnkr_browser.py` 의 것을 빌려 쓰는 것과
같다 — 그 조각들은 결제창에서 여러 번 틀려 가며 다듬은 것이라, 사이트마다 다시 쓰는 것보다
빌려 쓰는 편이 낫다.

| | |
|---|---|
| `index.ts` | 명령줄. 파이썬 판의 `parse_args`·`main` |
| `config.ts` | 설정·상태·로그 파일 자리 |
| `targets.ts` | 상품 주소 알아보기 (`parse_url`·`parse_target`) |
| `http.ts` | 세션·로그인 확인·429(곧장 창으로)·캡차 벽 (`new_session`·`get_page`) |
| `product.ts` | 상태 JSON 을 떼어내 재고를 읽는다 (`carve_json`·`find_product`·`read_stock`) |
| `browser.ts` | 크롬. 구매하기 · 구매 레이어 · 주문서 확인 · 결제하기 (`naver_browser.py`) |
| `order.ts` | 주문서까지 데려다 놓기 (`do_buy`·`say_arrived`) |
| `watch.ts` | HTTP 감시 루프 (`watch`·`handle_target`) |
| `window.ts` | 크롬 창에서 지켜보기 (`watch_in_browser`·`wait_for_human`·`buy_from_window`) |
| `pin.ts` | 간편결제 비밀번호 자판 읽기·누르기 (bnkr-test 에서 베낌) |
| `commands.ts` | 한 번 부르고 끝나는 것들 (`--status`·`--probe`·`--link`·`--buy`…) |

창 안에서 도는 자바스크립트 조각들은 파이썬 판의 것을 글자 그대로 가져왔다. 그것들이
왜 그렇게 생겼는지는 하나하나 데어 가며 알아낸 것이라, 옮기면서 손대지 않았다.
