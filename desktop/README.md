# AIO Task Manager — 롯데온 · 네이버 · 반다이남코 데스크톱 대시보드

세 원본을 **한 줄도 고치지 않고** 태스크마다 따로 띄워 관리하는 Electron + React 앱.

| 사이트 | 원본 | 들이는 것 |
|---|---|---|
| 롯데온 | `aio/node/src/lotte-test` | 빌드된 `node/dist/lotte-test/index.js` |
| 네이버 | `naver/ts` | TS 소스 `naver/ts/src/cli.ts` 를 **원본의 tsx 로** 그대로 (원본도 빌드 없이 tsx 로 돈다) |
| 반다이남코 | `aio/node/src/bnkr-test` (네이버페이 테스트 판) | 빌드된 `node/dist/bnkr-test/index.js` — 롯데와 같은 원본 프로젝트라 빌드도 같이 된다 |

```bat
cd desktop
npm install
npm start          :: main·worker·렌더러를 굽고 창을 띄운다
npm run typecheck  :: 세 설정 + 원본과 맞대 보기 (아래 '경로 별칭')
```

**윈도우에서 사용자 폴더가 한글이면** (`C:\Users\제영`) `electron.exe` 가 그 아래에서는 시작하자마자 아무 말 없이 죽는다
(2026-10-17). 그래서 `npm start` 는 `electron .` 대신 `scripts/start-electron.mjs` 를 부른다 — Electron 을 영문 경로
(`C:\aio-electron\<버전>`, `AIO_ELECTRON_DIR` 로 바꿀 수 있다)에 처음 한 번 복사해 두고 거기서 띄운다. 버전을 올리면 새로
복사한다. 맥·리눅스와 영문 경로에서는 아무것도 안 한다.

준비가 덜 된 사이트는 상단 오른쪽 알림(🔔)에 뜬다 (태스크가 있는 사이트만 — 누르면 펼친다). 롯데는 **원본 빌드**
(`node/` 에서 `npm run build`), 네이버는 tsx 가 없으면 **설치**(`naver/ts` 에서 `npm install`)
버튼이 있다. 로그인은 왼쪽 **프로필**에서 한다 (아래 '프로필'). 사이트마다 계정을 여럿 두고 태스크마다 고른다.
0.2 까지 콘솔 원본 명령으로 넣어 둔 로그인(롯데 `npm run lotte:test:cookie`, 네이버 `npm start -- --login`)은
처음 켤 때 프로필 하나로 옮겨 온다.

## 짜임

```
renderer (React) ──ipc──▶ main (TaskManager) ──fork──▶ worker.js ──import──▶ 원본 진입점
                           │  (MonitorManager)       ◀─ IPC(READY / WORKER_EXIT_REQUEST / FATAL) + stdout
                           │  (SessionManager)
                           └─ sites/{lotte,naver}.ts   (사이트마다 다른 것은 전부 여기)
```

SessionManager(프로필)도 원본 명령(`--login` · `--whoami` · `--pin`)을 같은 워커로 띄운다 (`main/legacy.ts`).
MonitorManager(모니터 — 사지 않고 재고만 본다)도 같은 워커로 원본의 감시 루프를 dry-run 으로 띄운다 (아래 '모니터').

화면과 TaskManager 는 `Task` 의 `site: 'lotte' | 'naver'` 만 안다. 원본을 어떻게 띄우는지는
**어댑터**(`src/main/sites/`)가 정해 돌려준다 — 진입점, 인자, 환경변수, 돌릴 파일 경로. 워커는
그것만 보고 원본을 들인다. 사이트를 하나 더 붙이려면 어댑터와 `src/shared/sites.ts` 에 넣는다.

| | |
|---|---|
| 프로세스 | 태스크 하나 = `child_process.fork` 워커 하나. 하나가 터져도 앱·다른 태스크는 산다. 원본의 전역 변수도 태스크끼리 안 섞인다 |
| 파일 | 태스크마다 `%APPDATA%/aio-task-manager/task-homes/<id>` — 설정·산 기록·로그·결제창 받아쓰기가 따로 쌓인다 |
| 설정 | 사이트의 씨앗 설정을 베끼고 **대상만 그 태스크의 상품 하나로** 바꾼다 (네이버는 카테고리 감시도 뺀다) |
| 계정 | 태스크마다 로그인 프로필을 고른다. 롯데 쿠키는 환경변수로, 네이버 세션은 워커가 원본의 세션 경로를 프로필 파일로 돌려서 |
| 비밀 | 쿠키·결제 비밀번호는 태스크 폴더에 **안 적는다.** `LOTTEON_COOKIE` · `LOTTEON_PG_PASSWORD` · `NAVER_PG_PASSWORD` 로만 (비밀번호는 태스크가 고른 프로필 것, 없으면 빈 값) |

### 원본이 파일을 어디에 쓰나

| | 롯데 | 네이버 |
|---|---|---|
| 설정 · 산 기록 | `LOTTEON_HOME` = 태스크 홈 | `--config` · `--state` = 태스크 홈 |
| 로그 · 결제창 받아쓰기 | `LOTTEON_HOME` 아래 | 원본이 `naver/` 에 박아 둠 → **워커가 쓰기를 태스크 홈으로 돌린다** |
| 로그인 | 프로필의 쿠키 (환경변수) | 원본이 `naver/naver_session.json` 을 읽고 쓰는 것을 → **프로필의 세션 파일로 돌린다** |

네이버 원본은 로그·받아쓰기·로그인 세션 경로를 바꿀 길을 안 열어 두었다 (`cli.ts` 에 절대 경로로 박혀 있다).
워커가 `appendFileSync` · `writeFileSync` · `existsSync` · `readFileSync` · `fs.promises.readFile/writeFile`
(Playwright 가 세션을 이것으로 읽고 쓴다)을 감싸 **표에 적힌 경로만** 태스크 홈·프로필 폴더로 돌린다
(`AIO_REDIRECTS`). 원본은 모른다.

세션 파일을 원본 자리에 복사해 넣었다 빼는 식으로는 안 된다. 원본은 시작할 때만이 아니라 **구매 창을 열 때마다**
(`browser.ts` 의 `openBuyer`) 세션 파일을 다시 읽는다 — 다른 프로필 태스크가 그 사이에 파일을 바꿔 넣으면 다른
계정으로 구매 창이 열린다. 돌리기는 프로세스마다라 그럴 일이 없고, 콘솔용 `naver/naver_session.json` 도 건드리지 않는다.

### 모드 → 원본 인자

| 모드 | 롯데 | 네이버 |
|---|---|---|
| 지켜보기 | (없음) | `--watch` |
| 한 번만 | `--once` | `--once` |
| 드라이런 | `--dry-run` | `--watch --dry-run` (혼자 쓰면 조회만 하므로) |
| 재고만 | `--status` | (옵션 없이 = 설정의 상품을 한 번 조회) |
| 지금 구매 | `--buy URL` | `--buy URL` |
| 드랍 | `--drop` (지켜보기 + 빠른 걸음) | 없음 — 원본에 `--drop` 이 없다 |

"어디까지"(`--action`)는 사이트마다 다르다 — 네이버에는 `agree` 가 없다. 고른 것이 **실제로 어디서
멈추는지**는 고른 프로필의 결제 비밀번호와 씨앗 설정에 달렸다 (네이버는 비밀번호 뒤 마지막 확인 `buy.finish_steps`
— 기본 `["결제내용에 동의", "결제"]`). 태스크 폼의 "어디까지" 아래에 원본 배너와 같은 말로 적어 준다.

### 간격 · 재시도

태스크 폼의 "간격 · 재시도" 칸. **비워 두면 씨앗 설정**이고, 칸의 흐린 글씨가 그 값이다. 적은 값은
어댑터가 **원본이 이미 읽는 설정 칸**으로 옮겨 태스크 홈의 설정에 적는다 — 원본은 모른다.

| 칸 | 롯데 원본 | 네이버 원본 |
|---|---|---|
| 확인 간격 | `poll_interval_seconds` — 씨앗의 하한 `min_interval_seconds` 아래로는 원본이 올려서 본다 | `check_interval_seconds` — **정수 초**라 올려 적는다. 상품 하나를 2초보다 촘촘히 보면 원본이 요청률로 거절하므로 폼이 막는다 |
| 재시도 · 간격 | `max_attempts`(= 재시도 + 1) · `retry_delay_seconds` — **재고 조회와 구매 시도** | `buy.max_attempts` · `buy.retry_delay_seconds` — **구매 시도만** (조회가 막히면 원본이 알아서 물러난다) |
| 사고 나면 | `stop_after_success` · `max_buys_per_run` | 같은 칸, `buy.` 아래 |
| 감시 시간 | 원본에 없다 → 매니저가 시간을 재서 멈춤(Ctrl+C). 끝나면 **완료** | 같음. 구매 창이 열려 있으면 그 창을 기다리는 것도 같다 |

"사고 나면 → 다음 재입고에도 또 삼" 은 `stop_after_success: false` 에 `max_buys_per_run: N` 이다.
원본은 한 번 돌 때 N 번 사면 감시를 끝낸다. 확인 간격·감시 시간은 반복해서 보는 모드(지켜보기·드라이런)
에서만 쓴다. 네이버 요청률 합(아래)도 태스크마다 정한 간격으로 센다.

**페이지 로드 뒤 대기 · 동작 사이 대기는 없다.** 두 원본 어디에도 그런 설정 칸이 없다 — 대기는
코드에 박혀 있다 (`browser_timeout_seconds` 는 기다리는 한도지 쉬는 시간이 아니다).

### 돌던 중에 고치기

돌고 있는 태스크도 ✎ 로 고친다. **상품 주소만** 바꾸려면 태스크 창(🖥)의 "상품 주소" 줄에서 바로 고친다 (복사도
거기서) — 같은 `saveTask` 라 규칙이 같고, 저장 전에 무엇이 될지 적어 준다. 다른 사이트 주소는 받지 않는다. 메인 표의
"링크" 칸은 누르면 전체 주소를 복사만 한다 (실수로 고치지 않게). 저장하면 (규칙은 `TaskManager.applyToLive`, 폼 위에
미리 적어 준다)

| 바뀐 것 | 어떻게 |
|---|---|
| 롯데 대상 칸만 (상품 주소·수량·옵션·상한가·이름) | **바로 반영.** 태스크 홈 설정의 `targets` 만 고쳐 쓴다 — 원본이 기다리는 사이에 다시 읽는다 (`watch.ts` 의 `reread`) |
| 그 밖 (간격·재시도·어디까지·모드·네이버의 모든 칸) | **다시 시작.** 원본이 실행 중에 다시 읽지 않는 칸이라 멈췄다 새 설정으로 띄운다. 표에 "재시작 대기" |
| 한 번 돌고 끝나는 모드 (한 번만·지금 구매·재고만) | 이번 실행에는 반영하지 않는다 — 다시 띄우면 그 일을 한 번 더 한다 (또 산다) |

**구매 도중에는 다시 시작하지 않는다.**

- 롯데: 원본이 "구매 가능, 바로 구매하기를 누릅니다" 를 찍은 뒤 **산 기록 파일을 다시 쓸 때까지** 미룬다. 원본이
  구매를 마치고(또는 접고) 기록을 확정하는 자리다. 롯데 원본은 Ctrl+C 에 바로 끝나서, 이게 없으면 주문서로
  가던 중에 끊긴다.
- 네이버: 따로 볼 것이 없다. Ctrl+C(첫 번째)가 하던 구매와 열린 구매 창을 원본이 스스로 기다려 준다.

미뤄 둔 사이에 ■ 를 누르면 다시 시작을 거둔다. 새 간격으로 네이버 요청률 합이 거부선을 넘으면 다시 시작하지
않고 바뀌기 전 설정으로 계속 돈다. 감시 시간은 다시 시작해도 처음 켠 때부터 이어서 잰다.

### 드랍 (롯데 `--drop`)

원본 `--drop` 은 인자 없는 플래그다. 감시(지켜보기) 걸음만 바꾼다 — `--buy`·`--status` 에는 걸리지 않는다.

- 드랍 확인 간격 `drop_interval_seconds`(씨앗 1초, 원본 바닥 0.5초) ±`drop_jitter_seconds`. 평소 하한
  `min_interval_seconds` 는 따르지 않는다.
- 재시도 쉼 `retry_delay_seconds` · 실패 뒤 쉬는 시간 `cooldown_minutes` → 0. 조회가 실패한 바퀴 뒤에만 한 번 평소
  간격으로 쉰다 (봇 차단 대비). 시간 제한은 없다 (원본 주석: 2026-09-26 에 없앴다 — 드랍 때만 켜고 끄는 모드라서).

태스크 폼에서 모드 **드랍**(롯데만)을 고르면 **드랍** 칸이 생긴다.

| 칸 | 어떻게 |
|---|---|
| 드랍 확인 간격 | 태스크 설정의 `drop_interval_seconds` (비우면 씨앗). "초고속" 은 따로 없다 — `--drop` 이 이미 빠른 걸음이고, 더 빠르게는 이 간격을 0.5초까지 |
| 드랍 시각 · 몇 분 전 | 원본에 시각이 없어서 **매니저가 예약한다.** ▶ 를 누르면 "예약" — 드랍 N분 전에 `--drop` 으로 띄운다. 비우면 ▶ 에 바로 띄운다 |

- 예약은 **앱이 켜져 있어야** 돈다 (앱을 닫으려 하면 묻는다). PC 가 잠들었다 깨도 0.5초마다 시계를 봐서 곧바로 띄운다.
- 드랍 시각이 오늘 이미 지났으면 내일로 잡는다. 30분 안쪽으로 막 지났으면 지금 띄운다 (드랍 직후에 ▶ 를 누른 것).
- 미리 띄울 때가 이미 지났으면 (드랍까지 몇 분 전보다 적게 남았으면) 바로 띄운다.
- 예약 중에 고치면 새 시각으로 다시 잡는다. ■ 로 예약을 거둔다. 돌던 중에 드랍 시각만 바꾸면 다시 시작하지 않는다
  (이미 띄웠다). 드랍 확인 간격을 바꾸면 다시 시작한다.
- 원본은 **품절 → 구매가능으로 바뀌는 순간**에만 산다 (`buy_on_restock_only`). 드랍 전에 띄워 두어야 드랍 전의
  "품절" 을 보고 풀리는 순간을 잡는다 — "몇 분 전" 을 0 보다 크게 두는 이유다. 끝낼 때는 **감시 시간**으로 정한다.
- 태스크마다 따로 두드린다. 드랍 태스크를 여럿 켜면 그만큼 촘촘해진다 (롯데온은 Imperva 봇 차단 뒤에 있다).

## 반다이남코 (`bnkr`)

롯데와 같은 길이다 (`src/main/sites/bnkr.ts`). 원본이 집·쿠키·비밀번호를 환경변수로 받는다 — `BNKR_HOME` = 태스크 홈,
`BNKR_COOKIE` = 프로필의 `bnkr-cookie.txt`, `BNKR_PG_PASSWORD` = 프로필의 결제 비밀번호 (없으면 빈 값). 씨앗은
`aio/bnkr_test_config.json` (없으면 `bnkr_buy_config.json`).

| | |
|---|---|
| 대상 | 주소가 아니라 gno. 태스크 주소에서 `gno=` 를 떼어 `{gno, ea, mode: "DIRECT", max_price, label}` 한 줄로 적는다. 담는 방식은 바로구매(DIRECT) 하나 |
| 태스크 설정 | 씨앗을 베끼고 대상만 바꾼다. **`discover`(목록 훑기)는 비운다** — 태스크는 상품 하나다. 쿠키·비밀번호는 비운다 |
| 모드 | 지켜보기 (없음) · 한 번만 `--once` · 지금 구매 `--buy <gno> --ea N` (원본이 상한가를 안 본다) · 드라이런 `--dry-run` · 재고만 `--status`. 드랍 없음 |
| 드라이런 | 원본이 **한 번 보고 끝난다** (`args.once \|\| run.dryRun`). 그래서 **모니터는 안 된다** — `SiteSpec.monitors: false`, 모니터 화면에 안 뜬다 |
| 어디까지 | open 주문서 · agree 필수 동의 · submit 결제창(네이버페이). 비밀번호가 있으면 씨앗의 `pg_finish` 까지 눌러 **사람 손 없이 결제된다** |
| 간격 · 재시도 | `poll_interval_seconds` (원본이 3초 밑으로 안 내린다) · `max_attempts` · `retry_delay_seconds` · `stop_after_success` · `max_carts_per_run` |
| 돌던 중에 | 상품 주소·수량·상한가·이름은 바로 반영 — 원본이 설정 파일이 바뀌면 기다림을 접고 다시 읽는다 (`watch.ts` 의 `reloadConfig`) |
| 로그인 | 매니저가 창을 띄운다 (`persist:login-bnkr-<id>`, `/member/login.do`). 살아 있나는 원본 `loginInfo` 와 같은 물음 (`member_login_check_ajax.do` 의 `authmemberno`). `MEMBER_TOKEN` 은 한 시간짜리 — 도는 원본은 새로 받아 쓰지만 프로필 파일은 그대로라, 오래 두었으면 다시 로그인한다 |
| 네이버페이 로그인 | 태스크 폼의 **네이버페이 로그인** 에서 네이버 프로필을 고르면 (`TaskDef.payProfileId`, `SiteSpec.payProfileSite`) 그 프로필의 `naver_session.json` 경로를 `BNKR_NAVER_SESSION` 으로 넘긴다. 원본이 크롬을 띄울 때마다 그 파일을 다시 읽어 네이버 쿠키를 CDP 로 같이 심는다 (주문서를 열 때마다 — 미리 띄운 창에도). 지켜보기의 사전 로그인은 심은 세션이 살아 있으면(`nid.naver.com/user2/help/myInfo` 가 nidlogin 으로 안 보내면) 사람을 기다리지 않는다. 죽었으면 경고하고 예전처럼 사람을 기다린다. 고르지 않았거나 프로필에 로그인이 없으면 로그에 적고 그대로 띄운다. 그 네이버 프로필은 이 태스크가 도는 동안 "사용 중" 이라 지우거나 로그아웃할 수 없다. 콘솔에서는 설정의 `naver_session` 에 경로를 적는다 |
| 알아 둘 것 | 씨앗의 `buy_on_restock_only: false` 면 알림(🔔)에 경고 (지금 팔고 있으면 바로 담는다). `prelogin_url` 이 있으면 지켜보기를 켤 때 크롬에 네이버 로그인 창이 먼저 뜬다 |

## 프로필 (로그인)

왼쪽 **프로필** — 사이트마다 로그인 프로필(계정)을 여럿 둔다. 태스크는 폼의 **로그인 프로필**에서 하나를 고른다
(폼에서 바로 새로 만들고 로그인할 수도 있다). 로그인은 창 안에서 사람이 직접 한다 (캡차·2단계 인증 포함). 매니저는
아이디·비밀번호를 보지도 적지도 않고, 로그인된 뒤의 쿠키·세션만 프로필 폴더에 적는다.

```
%APPDATA%/aio-task-manager/
├── profiles.json                  프로필 목록 (순서 · 사이트 · 이름)
└── profiles/<id>/
    ├── meta.json                  상태 (로그인 상태 · 마지막 로그인 · 마지막 확인)
    ├── lotte-cookie.txt           롯데 쿠키 한 줄 (Cookie: 줄 그대로)
    └── naver_session.json         네이버 세션 (원본 --login 이 적는 것과 같은 모양)
```

| | 롯데 | 네이버 |
|---|---|---|
| 로그인 창 | 매니저가 띄운다 (Electron, `persist:login-lotte-<id>` — 프로필마다 따로. 같은 프로필로 다시 로그인하면 로그인된 채로 열린다) | 원본 `--login` 이 띄운다 (Playwright) |
| 로그인됐나 | 창이 로그인 페이지를 벗어나면 원본과 같은 물음(`HEAD /p/order/mylotte/orderDeliveryList` → 200, 로그아웃이면 `/p/member/login` 으로 302)으로 본다 | 원본이 `NID_AUT`·`NID_SES` 를 보고 판정 |
| 저장 | 창의 lotteon.com 쿠키를 한 줄로 모아 `lotte-cookie.txt` 에 | 원본이 `naver/naver_session.json` 에 적는 것을 워커가 프로필의 `naver_session.json` 으로 돌린다 |
| 세션 확인 | 원본 `--whoami` (그 프로필의 쿠키로, 빈 폴더를 원본의 집으로) | 원본 `--whoami` (그 프로필의 세션으로 돌려서) |
| 태스크에 | `LOTTEON_COOKIE` 환경변수로 (태스크 설정에는 빈칸) | 세션 경로 돌리기 |
| 동시에 | 한 프로필로 태스크 여럿 — 원본은 크롬을 매번 빈 임시 프로필로 띄우고 쿠키를 심는다 | 한 프로필로 태스크·모니터 여럿 — 워커마다 같은 세션 파일을 읽기만 한다 (원본은 `--login` 때만 쓴다). 로그인 세션째로 막는 요청률은 프로필과 상관없이 네이버 합으로 막는다 (아래 '네이버 요청률 합'). 2026-10-06 전에는 한 프로필에 하나였다 |

- **로그인 프로필이 없어도 되는 모드**: 롯데 재고만·드라이런 (원본이 쿠키 없이 공개 페이지로 본다). 그 밖의 모드와
  네이버는 프로필이 있어야 저장·시작된다. 로그인 안 된 프로필은 고를 수 있다 — 띄우기 전에 로그인하면 된다.
- **로그아웃**은 프로필 폴더의 로그인 정보를 지운다 (롯데는 로그인 창의 저장소도 비운다). 사이트 쪽 세션을 끊지는
  않는다 — 원본에도 그런 명령이 없다. **지우기**는 프로필 폴더째 지우고, 그 프로필을 고른 태스크는 "프로필 없음"
  으로 돌린다. 그 프로필로 돌고 있거나 예약된 태스크가 있으면 둘 다 거절한다.
- 앱을 켤 때 로그인 정보가 있는 프로필을 하나씩 확인한다 (프로필마다 요청 하나). 태스크 출력에 원본의 "세션이
  끊겼습니다" 류 문구가 보이면 그 태스크의 프로필을 곧바로 **만료**로 돌린다. 로그인이 필요한 태스크는 상단 오른쪽 알림(🔔)과
  사이드바 **프로필** 옆 점으로 알린다.
- 로그인 창의 UA 에서는 `Electron/…` 과 앱 이름을 뗀다 — 속은 크롬 그대로다.
- **0.2 에서 옮기기**: 예전 `profiles.json`(사이트마다 계정 하나)은 처음 켤 때 `profiles.v1.json` 으로 남기고, 원본
  파일(롯데 씨앗 설정의 `cookie` · `naver/naver_session.json`)에 로그인 정보가 있는 사이트는 그것을 프로필 폴더로
  **베껴** 프로필 하나로 만든다. 원본 파일은 그대로 두므로 콘솔에서 돌리는 원본은 지금처럼 그것을 쓴다 — 그 뒤로는
  매니저의 프로필과 콘솔의 로그인이 따로 간다.
- **목록 되살리기**: `profiles.json` 이 없거나 0.2 형식인데 프로필 폴더(`profiles/<id>/meta.json`)가 이미 있으면 다시
  옮기지 않고 **폴더에서 목록을 되살린다.** 옮긴 뒤 `profiles.json` 만 옛 사본으로 돌아간 일이 실제로 있었다 (2026-09-26 —
  누가 되돌렸는지는 모른다). 다시 옮겼다면 원본 파일의 더 오래된 로그인으로 프로필이 겹치고, 그 뒤에 새로 로그인한
  프로필은 목록에서 빠졌을 것이다. `profiles.json` 은 옆에 쓰고 바꿔치기한다.

## 결제 비밀번호 (프로필마다)

간편결제 비밀번호는 **계정의 것**이라 프로필마다 하나 둔다. 사이트 공통으로 두면 다른 계정의 태스크가 그 비밀번호를
자판에 누른다 (몇 번 틀리면 결제 수단이 잠긴다). **프로필** 카드의 "결제 비밀번호 넣기" — 숫자 6자리를 두 번
(두 원본 다 6자리로 누른다. 다르면 받지 않는다).

| | |
|---|---|
| 저장 | `profiles/<id>/payment-pin.enc` — Electron `safeStorage` 로 암호화한 바이트 (윈도에서는 DPAPI: 이 PC 의 이 윈도 계정에서만 풀린다). 암호화를 쓸 수 없는 환경이면 저장하지 않는다 (평문으로 대신 적지 않는다) |
| 화면 | 있나 없나만 (`Profile.hasPaymentPin` = 파일이 있나). 값은 돌려주지 않는다 |
| 로그 | 자릿수만 ("결제 비밀번호: '메인' 프로필의 것 (6자리)") |
| 태스크에 | 띄우기 직전에만 풀어 `LOTTEON_PG_PASSWORD` · `NAVER_PG_PASSWORD` 환경변수로. **프로필에 없으면 빈 값을 적는다** — 사용자 환경변수나 원본 설정의 콘솔용 비밀번호가 새어 들지 않게. 태스크 설정에는 빈칸. 원본의 `--pin` 은 쓰지 않는다 (설정 파일에 평문으로 적고 끝나는 명령이고, 인자는 로그·명령줄에 보인다) |
| 모니터 | 쓰지 않는다 (빈 값) |
| 없으면 | 실패하지 않는다 — 롯데는 결제창에서, 네이버는 인증 화면에서 사람을 기다린다 |
| 있으면 | 롯데: 결제창 비밀번호 자판까지 — 결제 확정은 사람이. 네이버: 비밀번호 → 마지막 확인(`finish_steps`)까지 — **사람 손 없이 결제된다** |

- 비밀번호가 쓰이는 것은 사는 모드(지켜보기·한 번만·지금 구매·드랍)이고 "어디까지" 가 결제 단계일 때뿐이다
  (비우면 씨앗 설정의 `order_action`). 그런 태스크를 ▶ 로 띄우는데 프로필에 비밀번호가 없으면 먼저 묻는다
  ("결제 단계에서 사람이 넣어야 합니다" — 넣기 / 그래도 시작 / 취소). "전부 시작" 은 묻지 않고 태스크 로그에 적는다.
- 바꾸면 돌고 있는 태스크는 다시 시작할 때부터 새 비밀번호를 쓴다 (환경변수는 띄울 때 넘어간다).
- 로그아웃해도 남는다 (로그인 세션과 따로다). 프로필을 지우면 폴더째 지워진다.
- 매니저가 비밀번호를 쥐고 있지 않는다 — 띄울 때 풀어 넘기고 버린다. 원본 프로세스는 환경변수로 끝까지 들고 있다
  (롯데는 결제창에 올 때마다 읽는다).

### 콘솔용 간편결제 비밀번호 (`--pin`)

**프로필** 화면의 사이트마다 있는 **콘솔용** 칸 — 원본을 매니저 없이 직접 돌릴 때만 쓰인다 (원본 설정 파일에 하나라서
사이트 공통). **태스크는 이것을 쓰지 않는다.** 원본의 `--pin` 은 설정 파일에 적고 끝나는 명령이다.

| | 롯데 | 네이버 |
|---|---|---|
| 적기 | 원본 `--pin <숫자>` → 씨앗 설정 옆 `lotteon_test_config.json` 의 `pg_password` | 원본 `--pin <숫자> --config <씨앗>` → `buy.pg_password` (다른 칸은 그대로) |
| 지우기 | 원본에 명령이 없다 → 매니저가 `pg_password` 한 칸만 비운다 | 원본 `--pin clear` |

콘솔에서 `--pin` 으로 넣은 것과 한 곳이다 (원본 설정 파일에 평문). 화면·로그에는 자릿수만 나온다. 원본이 환경변수를
설정 파일보다 먼저 읽으므로, 비밀번호가 환경변수로 들어와 있으면 프로필 화면이 그렇다고 알린다. 적을 때 비밀번호가
원본 명령의 인자로 잠깐 지나간다 — 콘솔에서 `--pin 123456` 을 치는 것과 같다.

## 디스코드 웹훅 (두 사이트 공통)

**설정** 창 맨 위. 알림은 원본이 보낸다 (롯데 `notify.ts` — 주문서·결제창 열림, 안 삼, 세션 끊김, 결제 완료 /
네이버 `discord.ts` — 재입고, 신상품, 차단, 구매 알림). 무엇을 보낼지도 원본 설정(`discord_notify` · `buy.notify`)이
정한다. 매니저는 **주소만** 하나로 모은다.

- 두 원본이 같이 읽는 설정 파일이 없어서 주소는 매니저 `settings.json` 의 `discordWebhookUrl` 에 둔다. 원본 설정
  파일은 고치지 않는다 — 콘솔에서 돌리는 원본은 지금처럼 제 설정의 웹훅을 쓴다.
- 태스크를 띄울 때 태스크 설정의 `discord_webhook_url` 에 넣는다. 네이버는 `DISCORD_SMARTSTORE_WEBHOOK_URL`
  환경변수로도 넘긴다 (원본이 환경변수를 먼저 본다). 롯데 원본은 웹훅 환경변수를 안 받는다.
- 비워 두면 사이트마다 씨앗 설정의 웹훅. 롯데는 씨앗에 없으면 원본처럼 `bnkr_buy_config.json` 것을 빌려 쓴다 —
  원본은 그걸 `LOTTEON_HOME`(태스크 홈)에서 찾다 못 찾으므로, 빌려 쓰기는 매니저가 해서 태스크 설정에 넣는다.
- **보내 보기** 는 매니저가 시험 메시지 하나를 직접 보낸다 (디스코드가 204 로 받으면 성공). 설정 창에 사이트마다
  지금 알림이 어디로 가는지(공통·씨앗·빌려 씀, 주소 끝 몇 글자)가 보인다.

## 태스크 창

표의 🖥 — 태스크 하나의 상태와 로그를 따로 띄운 창에서 본다. 태스크마다 창 하나 (다시 누르면 그 창을 앞으로),
여러 태스크의 창을 같이 연다. 태스크를 지우거나 앱을 닫으면 같이 닫힌다.

### 열리기 전 대기열 (롯데)

롯데 태스크 창의 **대기열 보기** — 켜기 전에 줄이 얼마나 긴지 보고 언제 켤지 고른다. 켜면 main 이 10초마다 **쿠키 없이**
상품 페이지(대기열이 서 있으면 숨은 칸 isWait·waitCnt·limitCnt·session_time_out)와 상품 API(열리는 시각)를 읽는다
(`main/queueWatch.ts` · 어댑터의 `peekQueue`). **줄에 서지 않는다** — 줄에 서는 것은 대기 화면 스크립트가 순번 쿠키로
물을 때다. 셈은 원본 `tracer.ts` 의 gateOf · `product.ts` 의 opensAtOf 를 옮겨 적은 것이다 (원본 모듈은 main 에
들이지 않는다 — 들이면 제 집에 설정·로그를 만든다). 창을 닫거나 "그만 보기" 를 누르면 멈춘다.

| 칸 | 무엇 |
|---|---|
| 줄 | 지금 줄에 선 사람 · 1분 전보다 몇 명 늘었나 |
| 열리는 시각 | 판매 시작 전이면 그 시각, 예약배송이면 예약주문 시작 (열리기 전엔 null 이라 배송 안내 줄에서 읽는다) |
| 지금 서면 기다릴 어림 | 줄 ÷ "빠지는 속도 어림" (기본 2.5명/초, 고칠 수 있다) |

**확인 회차** — 원본은 회차를 세어 찍지 않는다. 네이버는 확인할 때마다 상품마다 "이름 — 품절 (재고 0)" 을 찍어서
그 줄을 센다. 롯데는 바뀐 것이 있을 때만 줄을 찍고, 기다리는 줄("다음 확인 N초")은 **화면(TTY)일 때만** `\r` 로
고쳐 쓴다 (`ui.ts`). 그래서 롯데 태스크는 워커가 표준출력을 화면처럼 보이게 하고(`AIO_TTY`), main 이 `\r` 로 고쳐
쓴 꼬리를 상태 줄로 받는다. 남은 초가 다시 올라가거나 같은 숫자를 새로 쓰면 한 바퀴다. 원본에서 `isTTY` 를 보는
곳은 `ui.ts` 두 줄뿐이고, `NO_COLOR` 라 색·표 모드는 안 켜진다 — 줄 모양은 그대로다.

**단계** (원본의 말로 알아본다, 어댑터의 `progress`)

| 단계 | 롯데 | 네이버 |
|---|---|---|
| 확인 중 | 확인 회차가 올라갔다 | 같음 |
| 구매 중 | "구매 가능, 바로 구매하기를 누릅니다" | "구매 가능, 구매하기를 누릅니다" |
| 결제 단계 | "…크롬 창에서 직접 해주세요" (주문서·결제창이 열렸다) | "…창에서 직접 해주세요/넣어주세요", "구매 창 N개가 열려 있습니다", "간편결제 비밀번호까지 넣었습니다" |
| 결제 완료 | "결제 완료 — …" | "⭐ 결제 완료", "⭐ 마지막 확인까지 눌렀습니다" |

- **⏸ 일시정지** — 보기만 멈춘다. 로그는 계속 받고, 멈춘 뒤 몇 줄이 더 왔는지 적어 준다.
- **📸 캡처** — 이 창의 모습(PNG)과 그 태스크의 로그(텍스트)를 태스크 폴더에 `task-watch-<시각>.png/.txt` 로 적는다.
- 창이 없는 태스크에는 아무것도 보내지 않는다. 있으면 제 태스크의 로그 줄만 (120ms 씩 묶어서), 상태가 바뀔 때만.

## 모니터

사이드바 **모니터** — 사지 않고 재고만 본다. 발견하면 알리고, 원하면 사람이 눌러 구매 태스크로 넘긴다. 태스크와 따로
돈다 (`monitorManager.ts` · `monitorStore.ts`) — 태스크 목록·태스크 파일을 쓰지 않는다. 워커는 태스크와 같다.

**어떻게 사지 않고 보나** — 원본의 감시 루프를 **dry-run** 으로 돌린다. 원본에 이미 있는 모드라 워커가 가로챌 것이 없다.

| | 롯데 | 네이버 |
|---|---|---|
| 인자 | `--dry-run` (씨앗 하한 `min_interval_seconds` 보다 촘촘하면 `--drop` 도) | `--watch --dry-run --config <모니터 홈> --state <모니터 홈>` |
| 로그인 | 안 쓴다 — 재고 API 가 공개. 구매로 넘길 때만 프로필이 있어야 한다 | 프로필 세션 (태스크처럼 세션 경로를 돌린다) |
| 발견 | 원본이 dry-run 구매 자리에서만 찍는 `[dry-run] 여기서 바로 구매하기를 눌렀을 것입니다 — URL` | `[dry-run] 여기서 구매하기를 눌렀을 것입니다 — URL` |
| 재고 판정 | `[키] 판정 품절 ← …` | `이름 — 품절 (재고 0개)` |
| 확인 회차 | 제자리 상태 줄의 "다음 확인 N초" (`AIO_TTY`) | 확인마다 찍는 재고 줄 |

발견 줄은 원본의 구매 판단(재입고 순간 · 상한가 · 네이버는 옵션 재고)을 통과해야만 찍힌다 — 이 줄 말고는 발견으로
보지 않는다 (오탐 방지). 원본 설정은 모니터 홈(`monitor-homes/<id>/`)에 **원본 파일 이름 그대로**
(`lotteon_test_config.json` · `smartstore_config.json`) 쓴다 — 씨앗을 베끼고, 대상은 모니터의 상품 하나, 쿠키·비밀번호·
웹훅은 비우고, 발견한 뒤에도 원본이 끝나지 않게 `max_buys_per_run: 1000000` · `stop_after_success: false` ·
`cooldown_minutes: 0`. "재입고 순간에만 감지" 는 원본의 `buy_on_restock_only` 다 — 끄면 지금 팔고 있어도 발견이다.
이 칸들이 원본 타입과 맞는지는 `contract.ts` 가 본다.

```
%APPDATA%/aio-task-manager/
├── monitors.json            모니터마다 정의(def)와 마지막 상태(state · popupOpen)
├── monitor-homes/<id>/      원본 설정 · 원본이 제 집에 쓰는 것 · "로그 저장" 파일
└── monitor-logs/<id>.log    모니터의 로그 (5MB 넘으면 <id>.1.log 로 밀어 둔다)
```

- **발견하면** 상태가 "재고 발견" 이 되고 모니터는 **계속 본다.** 메인 창 위에 🔔 알림 (모니터 창이 닫혀 있어도),
  모니터 창에 🎯 재고 발견 판, 앱이 뒤에 있으면 작업 표시줄이 깜빡이고, 그 사이트 태스크의 웹훅(공통 → 씨앗 → 빌려 씀)
  으로 디스코드. dry-run 이라 원본은 보내지 않는다.
- **구매 전환** — "재고 발견 시: 구매 태스크로 전환" 으로 만든 모니터에만 🛒 버튼이 뜬다. **저절로는 안 한다** — 눌러야
  하고 한 번 더 묻는다. 누르면 모니터를 멈추고(감시는 할 일을 마쳤고, 구매 태스크와 요청률을 나눠 쓰지 않게 먼저 비킨다) 같은 대상·같은
  프로필로 **지금 구매**(`--buy URL`) 태스크를 만들어 띄운다. "지켜보기" 로 만들지 않는 것은 그게 재입고 순간에만 사서
  이미 팔고 있는 물건을 사지 않기 때문이다.
- **일시정지** — 원본에 없어서 멈췄다가 재개할 때 다시 띄운다. 회차는 이어서 센다. 그 사이에 풀린 재입고는 놓칠 수
  있다. 원본의 dry-run 은 재고 기억을 메모리에만 두어서, 다시 띄운 뒤 "재입고 순간에만" 이면 이미 팔고 있는 것은 다시
  발견하지 않는다.
- **간격** — 롯데는 0.5초까지 (씨앗 하한보다 짧으면 드랍 걸음, 봇 차단 경고). 네이버는 2초 아래는 원본이 거절해서
  막고, 권장선(10회/분 — 6초보다 짧으면)을 넘으면 경고한다.
- **네이버는 태스크와 같이 센다** — 요청률 합(아래 '네이버 요청률 합')에 모니터도 들어간다. 같은 프로필로 태스크·모니터를
  같이 돌릴 수 있다 (사이트 설정 `oneTaskPerProfile` 이 켜진 사이트만 "이 프로필은 이미 실행 중입니다" 로 막는다 — 지금은 없다).
- 도는 중에 고치면 바뀐 설정으로 다시 띄운다. 지우면 멈추고 모니터 폴더·로그 파일도 지운다. 모니터가 쓰는 프로필은
  지우거나 로그아웃할 수 없다.
- **모니터 창** — 모니터마다 창 하나 (`#monitor/<id>`). 닫아도 모니터는 계속 돈다. 열려 있나(`popupOpen`)를 적어 두는데,
  앱을 닫느라 닫힌 창은 적지 않는다 — 다음에 켰을 때 마지막에 열려 있었는지 안다 (창을 저절로 열지는 않는다).
  **📸 로그 저장** 은 로그(텍스트)와 창 모습(PNG)을 모니터 홈에 적는다.
- 앱을 닫으면 모니터도 멈춘다. 앱이 꺼질 때 돌던 모니터는 다음에 켤 때 "중지됨" 이고, 회차·발견 시각·로그는 남는다.

## 워커의 방어 (`src/worker/worker.ts`)

### process.exit 가로채기

원본을 들이기 **전에** `process.exit` 를 바꿔 둔다.

1. main 에 `WORKER_EXIT_REQUEST {code}` 를 보내고, IPC 가 비워진 뒤 진짜로 끝낸다
2. `INTERCEPTED_EXIT_<code>` 를 던져 원본의 나머지 줄이 돌지 않게 한다
3. 그 뒤로는 표준출력과 원본 로그 파일 쓰기를 막는다 — 롯데 원본의 `.catch` 가 우리가 던진 것을
   받아 `✖ INTERCEPTED_EXIT_0` 을 적어서, 성공한 판이 실패처럼 보였다

워커를 살려 두지 않고 끝내는 이유: 원본은 exit 로 브라우저 연결을 끊는 것에 기댄다. 롯데 크롬
창은 detach 라 남는다. 네이버(Playwright) 창은 프로세스와 같이 죽으므로, 원본이 스스로 사람이
창을 닫을 때까지 기다린 **뒤에야** exit 를 부른다.

상태: exit(0) 청 → **완료**, exit(≠0) 청 → **실패**, 청 없이 죽음 → **터짐**, 사람이 멈춤 → **멈춤**.
원본에서 잡히지 않은 예외는 `FATAL` 로 올라와 **실패**가 된다.

### 화면처럼 보이기 (`AIO_TTY`)

롯데 태스크만. 원본을 들이기 전에 `process.stdout.isTTY` 를 true 로 둔다 — 원본이 기다리는 줄을 찍게 하려는
것이다 (위 '태스크 창' · '모니터'). main 은 표준출력을 터미널처럼 읽는다: 줄 안의 `\r` 뒤 마지막 조각이 그 줄이고, 줄 끝이
안 온 꼬리를 `\r` 로 고쳐 쓴 것은 상태 줄이다 (`legacy.ts` 의 `eachLine`).

### 멈춤 = Ctrl+C

윈도우에서는 자식에게 시그널을 못 보낸다. 워커가 IPC `STOP` 을 받아 원본의 SIGINT 처리기를 태운다.

| | 롯데 | 네이버 |
|---|---|---|
| ■ 멈춤 (한 번) | 산 기록을 적고 바로 exit | 감시를 끊는다. **구매 창이 열려 있으면 사람이 닫을 때까지 기다린다** |
| 안 끝나면 | 6초 뒤 죽인다 | 기다린다 — 4초 뒤 로그에 이유를 적는다 |
| **강제** (멈추는 중에 한 번 더) | 두 번째 Ctrl+C, 3초 뒤 죽인다 | 두 번째 Ctrl+C = 원본이 창째로 끝낸다 |

앱을 닫을 때도 같다. 다 멈추고 기다린 뒤, 구매 창을 붙든 태스크가 남으면 **기다릴지 강제로
끝낼지 묻는다** (강제로 끝내면 결제 중인 창도 닫힌다).

### 네이버 요청률 합

네이버 원본은 요청률이 권장선(10회/분)을 넘으면 경고하고 거부선(30회/분)을 넘으면 거절한다.
그런데 원본은 **프로세스 하나 안의** 상품 수로만 센다 — 태스크를 프로세스로 가르면 각자는 한도
아래인데 합치면 넘는다. 그래서 TaskManager 가 돌고 있는 네이버 태스크와 **모니터**의 합을 센다 — **프로필이 달라도
더한다** (이 PC 에서 나가는 요청은 IP 하나로 모인다). 모니터를 띄울 때도 같은 합으로 본다. 권장선을
넘으면 로그에 경고, 거부선을 넘으면 **띄우지 않는다.** 씨앗 설정의 `check_interval_seconds` 가
10초면 태스크당 6회/분이라 다섯 개까지 뜬다 (태스크가 확인 간격을 정했으면 그 간격으로 센다). 지금 구매·재고만은
한 번 보고 끝나서 세지 않는다.

## 경로 별칭 (`@lotte/*` · `@naver/*`)

`tsconfig.legacy.json` 이 원본 소스를 별칭으로 가리키고, `src/legacy/contract.ts` 가 **타입만**
들여 우리가 원본에 넘기는 것과 맞대 본다 — `--action` 값, 롯데 설정의 대상 한 줄(`TargetSpec`),
네이버 요청률 선, 네이버 마지막 확인 칸(`finishSteps`), 간격·재시도 칸, 롯데 로그인 경로(`LOGIN_PATH`),
비밀번호·웹훅 칸.
원본이 바뀌어 어긋나면 `npm run typecheck` 가 거기서 깨진다. 아무것도 굽지 않는다 (`noEmit`).

런타임에는 별칭을 쓰지 않는다. 워커가 원본을 **원래 자리에서** 들인다 — 원본이 제 위치
(`import.meta`)로 설정·세션 파일을 찾고, 제 `node_modules` 에서 셀레니움·Playwright 를 찾기
때문이다. 묶어 옮기면 둘 다 어긋난다. 원본 위치는 설정 창에서 바꾼다. 별칭은 기본 배치
(`aio/node`, `../naver/ts`)를 가리킨다.

## 알아 둘 것

- **같은 프로필의 태스크끼리는 계정이 같다** (롯데·네이버 둘 다). 같은 상품 태스크를 한 프로필로 여럿 켜면 같은 계정으로
  주문서가 여러 번 열린다. 원본이 "계정이 하나" 라 담기·주문을 한 줄로 세우던 것이 프로세스를 가르면서 풀린다. 계정을
  가르려면 프로필을 따로 둔다. 태스크 폼은 고른 프로필을 지금 다른 태스크·모니터가 쓰고 있으면 알려 준다.
- **네이버 프로필로 돌고 있는 중에 그 프로필로 다시 로그인하면**, 원본 `--login` 이 세션 파일을 새로 쓰는 순간 다른
  태스크가 구매 창을 열며 그 파일을 읽다 반쯤 쓰인 것을 볼 수 있다 ("세션 파일을 읽지 못했습니다"). 다시 로그인은 그
  프로필의 태스크를 멈추고 한다.
- 드라이런은 두 원본 다 디스코드로 보내지 않는다 (무엇을 보냈을지 로그에만 적는다 — 네이버는 보낼 내용을 JSON 째로 찍는다).
  모니터의 재고 발견 알림은 매니저가 따로 보낸다.
- 네이버 지켜보기·한 번만은 디스코드 웹훅이 없으면 원본이 거절한다 (알림 🔔 에 뜬다).
- 산 기록은 태스크 폴더마다 따로다. 다시 사게 하려면 로그 패널의 **산 기록 지우기** (네이버는
  원본 `--reset` 처럼 `_buy` 만 지우고 재입고 기준선은 남긴다).
- 0.1 의 설정(`legacyRoot` · `templateConfig`)과 `site` 없는 태스크는 롯데로 읽는다.
- 0.2 의 태스크에는 로그인 프로필이 없다 — 롯데 재고만·드라이런 말고는 ✎ 로 프로필을 골라야 돈다 (알림 🔔 에 뜬다).
